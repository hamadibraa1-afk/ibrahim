# تجربة طمأنينة على اللابتوب

هذا الدليل يشغّل المنصة كاملة على جهاز واحد: قاعدة البيانات والـ API وخدمة الأزمات وتطبيق المريض وبوابة الأخصائيين.
البيانات تجريبية والمفاتيح للتطوير فقط. **لا تُدخل بيانات مرضى حقيقيين.**

## 1. المتطلبات

- **Docker Desktop** (Windows أو macOS) أو Docker Engine على Linux.
  - خصّص له 6 GB ذاكرة على الأقل: Settings → Resources.
  - على Mac بمعالج Apple (M1/M2/M3/M4): فعّل Settings → General → **Use Rosetta for x86_64/amd64 emulation**، لأن SQL Server يعمل بنسخة amd64 فقط.
- **Git** لتنزيل المشروع.
- متصفح Chrome أو Edge أو Firefox.
- مساحة فارغة نحو 10 GB.

## 2. التشغيل

```bash
git clone https://github.com/hamadibraa1-afk/ibrahim.git
cd ibrahim
git checkout claude/brave-bardeen-3nott4
cd tamaneen
docker compose up --build
```

- أول تشغيل يأخذ 5 إلى 15 دقيقة لتنزيل الصور وبنائها. المرات التالية أسرع بكثير.
- المنصة جاهزة حين يظهر في السجل `Development seed:` من خدمة `api`.
- للإيقاف: `Ctrl+C`، ثم `docker compose down`.
- لمسح كل البيانات والبدء من جديد: `docker compose down -v`.

| ماذا | الرابط |
|---|---|
| تطبيق المريض | http://localhost:3000 |
| بوابة الأخصائيين | http://localhost:4200 |
| صندوق الرسائل التجريبي (رموز التحقق) | http://localhost:5080/dev/inbox |

لا يوجد مزود رسائل نصية في التجربة. كل رمز تحقق "يُرسل" يظهر في **صندوق الرسائل التجريبي** بدل الجوال أو البريد.

## 4. سيناريو التجربة من جانب المريض

1. افتح http://localhost:3000. اللغة الافتراضية عربية، وزر اللغة أعلى الصفحة يحوّل إلى الإنجليزية ويقلب الاتجاه فورًا.
2. **لنبدأ معًا**: أجب عن أسئلة الأهلية (العمر 18 أو أكثر، والمدينة من مدن التجربة).
3. **إنشاء الحساب**: اختر اسمًا مستعارًا، وأدخل جوالًا مثل `0551234567` أو بريدًا، وكلمة مرور قوية من 12 حرفًا على الأقل.
4. **رمز التحقق**: افتح http://localhost:5080/dev/inbox وانسخ الرمز المكوّن من 6 أرقام.
5. احفظ **رموز الاسترجاع**، ثم وافق على الموافقات، وأدخل بيانات الأمان (رقم تواصل وشخص موثوق).
6. **اختر المسار**:
   - "تحدث مع رفيق": محادثة استقبال بالذكاء الاصطناعي، ثم الملخص (تستطيع تصحيحه)، ثم الاستبيانات PHQ-9 وGAD-7. بعدها تنتظر مراجعة المشرف (القسم 5-أ)، وتنتقل صفحة الانتظار وحدها إلى الاقتراحات حين يعتمدها.
   - "احجز مباشرة": فحص أمان قصير، ثم اختيار أخصائي وموعد.
7. بعد الحجز: صفحة **مواعيدي** (تفاصيل، إعادة جدولة، إلغاء)، و**الرئيسية**، و**تسجيل المزاج**، و**الواجبات**، و**خطة الأمان**، و**الإعدادات** (الملف، الأمان والمصادقة، الإشعارات، بيانات الأمان، الخصوصية وسجل الوصول).
8. **زر "مساعدة فورية"** موجود في كل صفحة. داخله زر "اطلب أن يتصل بي مختص الآن" يفتح حالة أزمة حرجة ويقفل المحادثة.

> بدون مفتاح Anthropic يرد "رفيق" بنموذج تجريبي ثابت الأسئلة. لتجربة Claude الحقيقي، شغّل:
> `ANTHROPIC_API_KEY=sk-ant-... docker compose up` (على Windows PowerShell: `$env:ANTHROPIC_API_KEY="sk-ant-..."; docker compose up`).

## 5. سيناريو التجربة من جانب الأخصائيين

افتح http://localhost:4200 في **نافذة أخرى أو متصفح آخر**، حتى تبقى جلسة المريض مفتوحة. نسيت كلمة المرور؟ رابط «نسيت كلمة المرور؟» في صفحة الدخول، والرمز يصل إلى الصندوق التجريبي.

### أ. مراجعة الفرز (S03): المشرف
1. ادخل بحساب `fahad@staff.tamaneen.dev`، ثم افتح **قائمة الفرز** من القائمة الجانبية.
2. تظهر في الطابور الحالات التي أرسلها المرضى بعد الاستقبال، مرتبة بمستوى الخطر والوقت المتبقي. فتح الحالة **يحجزها لك 15 دقيقة**، حتى لا يعمل عليها مشرف آخر في الوقت نفسه.
3. راجع ملخص المريض والدرجات وفحص C-SSRS والأخصائيين المقترحين، ثم اختر القرار:
   - **اعتماد**: يرى المريض الاقتراحات فورًا ويحجز.
   - **تعديل مستوى الخطر** أو **إعادة توجيه** أو **تصعيد إلى طوارئ** أو **إغلاق مع إحالة**. كلها تطلب سببًا.
4. خفض المستوى من 3 أو 4 ينتظر **توقيع المسؤول السريري** (`lead@`). لا يمكن خفضه أبدًا تحت مستوى أزمة مفتوحة أو حديثة.

### ب. لوحة الأخصائي وملف المريض (S01 وS02)
1. ادخل بحساب الأخصائي الذي حجز معه المريض (مثلًا `sara@`). تظهر لوحتك: المواعيد، والملفات التي تنتظر مراجعتك، ومستوى الخطر، وتنبيهات الأزمات.
2. **«مراجعة الملف»** يفتح صفحة ملف المريض، وفيها:
   - كل جملة في الملخص مربوطة بكلام المريض الذي جاءت منه؛ اضغط «المصادر» لترى الرسائل.
   - محادثة الاستقبال، والدرجات بندًا بندًا، وC-SSRS، وتصحيحات المريض.
   - **اعتماد الملف**، و**رفع مستوى الخطر** مع سبب، و**إطلاق تنبيه طوارئ** يدويًا.
3. كل فتح للملف يُسجَّل، ويراه المريض في سجل الوصول.

### ج. تجربة الأزمة (S04)
1. من حساب المريض: اكتب في تسجيل المزاج أو المحادثة عبارة خطر واضحة، مثل «ما عاد أتحمل، أبي أموت الليلة»، أو اضغط زر **«مساعدة فورية»** أعلى أي صفحة.
2. عند المريض تظهر أرقام الطوارئ فورًا، وتُفتح حالة طارئة، وتُقفل المحادثة.
3. في بوابة الأخصائيين يصل **تنبيه فوري** إلى المشرف والمناوب (`khalid@`) وأخصائي المريض. «إحالة للمناوب» من اللوحة تطلب ملاحظة.
4. افتح **غرفة الطوارئ** (وحدة الأزمات). الرابط في التنبيه يفتح الحالة نفسها. يمكنك:
   - **استلام** الحالة: بعدها تصبح صاحبها، ولا يتصرف فيها غيرك إلا المشرف أو المسؤول السريري.
   - **كشف رقم التواصل** و**عرض كلام المريض**: كلاهما يطلب رمز مصادقة جديدًا، ويُسجَّل.
   - **اتصال**: يُسجَّل، ثم يسألك عن النتيجة.
   - **تم التواصل**: يطلب ملاحظة.
   - **تسليم لزميل**: يقبله الزميل أولًا.
   - **إغلاق بنتيجة وسبب**: للمشرف أو المسؤول السريري فقط. الإغلاق «تعذّر الوصول» يحتاج توقيع المسؤول السريري، ويُضاف موعد مراجعة بعد 72 ساعة.
5. بعد الإغلاق تُفتح المحادثة للمريض من جديد. يرى المريض في **سجل الوصول** (الإعدادات ← الخصوصية) من اطّلع على بياناته ومتى.

> أثناء الأزمة لا يستطيع المريض حذف حسابه، ويظهر له السبب.

## 6. مشاكل شائعة

| المشكلة | الحل |
|---|---|
| `port is already allocated` | منفذ مستخدم (3000 أو 4200 أو 5080 أو 5090 أو 14333). أغلق البرنامج الذي يستخدمه، أو غيّر المنفذ الأيسر في `docker-compose.yml`. |
| خدمة `sql` لا تصبح healthy على Mac | فعّل Rosetta (القسم 1) وأعد التشغيل. |
| "رمز التحقق غير صحيح" للموظف | تأكد أن ساعة الجوال واللابتوب مضبوطة تلقائيًا. انتظر رمزًا جديدًا، فكل رمز يُقبل مرة واحدة. |
| المتصفح يخرجني بعد الدخول | استخدم `http://localhost` وليس عنوان IP، وجرّب نافذة خاصة. |
| صفحة المريض تقول إن الخدمة غير متاحة | انتظر حتى تكتمل خدمة `api` وتظهر رسالة `Development seed:`. |
| أريد البدء من الصفر | `docker compose down -v` ثم `docker compose up`. |

## 7. ما ليس في هذه التجربة

- الرسائل النصية والبريد: تظهر في الصندوق التجريبي فقط.
- مكالمة الفيديو: رابط الجلسة تجريبي.
- تسجيل الدخول بـ Passkeys، وشاشة الرسائل مع الأخصائي، وتصدير ملف البيانات.
- ترجمات الاستبيانات العربية تحتاج اعتمادًا سريريًا قبل الإطلاق.
