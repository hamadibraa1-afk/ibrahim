# نظام الاقتراحات الرقمي — جمعية الشارقة الخيرية

**Digital Suggestions System** — تطبيق ويب كامل (.NET 8 + Angular 17 + SQL) لدورة
المقترحات الداخلية، مبني على نموذج **SCI-M-02-F-01 (الإصدار 02)** الرسمي.

---

## الجديد في هذا الإصدار

| الميزة | الوصف |
|---|---|
| **تسجيل دخول حقيقي** | اسم مستخدم وكلمة مرور، مع زر إظهار/إخفاء كلمة المرور |
| **الملف الشخصي** | عرض البيانات الوظيفية وتغيير كلمة المرور |
| **مطابقة النموذج الرسمي** | آلية التطبيق، أسباب التقديم، 6 خانات أثر، تصنيف اللجنة الخماسي |
| **مرحلة القرار التنفيذي** | خطوة مستقلة بعد توقيع اللجنة، كما في النموذج |
| **توليد النموذج معبَّأً (PDF)** | نسخة رسمية جاهزة للطباعة — **بدون اسم مقدّم الطلب** |
| **نظام الإشعارات** | جرس مع عدّاد، ورصد تلقائي لتجاوز المهل الزمنية |
| **هوية بصرية جديدة** | ألوان مستخلصة مباشرة من شعار الجمعية |

## التشغيل السريع (SQLite — بدون أي إعداد)

```bash
# نافذة 1 — الخادم
cd api/ProposalSystem.Api
dotnet restore
dotnet run          # http://localhost:5199

# نافذة 2 — الواجهة
cd web
npm install
ng serve            # http://localhost:4200
```

### حسابات الدخول التجريبية

كلمة المرور للجميع: `Passw0rd!`

| الرقم الوظيفي | الاسم | الدور |
|---|---|---|
| `EMP-1001` | إبراهيم عبدالجليل حمد | مدير النظام |
| `EMP-1002` | سارة المنصوري | موظف فرز |
| `EMP-1003` | قاسم الذوخي | عضو لجنة |
| `EMP-2001` | أحمد سالم | موظف |

> ⚠ غيّر كلمات المرور فوراً قبل أي استخدام فعلي.

## التشغيل على SQL Server

1. شغّل `database/01_create_database.sql` ثم `database/02_seed_data.sql`.
2. في `api/ProposalSystem.Api/appsettings.json`:
   ```json
   "DatabaseProvider": "SqlServer",
   ```
   وعدّل نص الاتصال `SqlServer`.
3. **مهم:** كلمات المرور لا يمكن توليدها من SQL (تستخدم PBKDF2). شغّل مرة واحدة:
   ```bash
   dotnet run --seed-passwords
   ```
   يعيّن `Passw0rd!` لكل مستخدم لا يملك تجزئة صالحة، ثم يخرج.
4. شغّل الـ API عادة: `dotnet run`

## دورة العمل

```
تقديم الموظف
   ↓
الفرز الأولي         ← اسم مقدّم الطلب مخفي
   ↓ (قبول / إعادة للتعديل / رفض)
لجنة دراسة المقترحات ← تصنيف + دراسة + توصية + توقيعات
   ↓ (عند اكتمال توقيع جميع الأعضاء)
قرار الإدارة التنفيذية
   ↓
مقبول / مرفوض  → شهادة شكر للمقبول
```

## المرفقات

- حتى **10 ملفات** لكل مقترح، بحد إجمالي **15 ميجابايت**، و**10 ميجابايت** للملف الواحد.
- الملفات تُخزَّن في `api/ProposalSystem.Api/App_Data/attachments/` باسم عشوائي.
- **عند النسخ الاحتياطي، انسخ قاعدة البيانات ومجلد `App_Data` معاً.**

## النموذج الرسمي (PDF)

من صفحة "مقترحاتي" أو لوحة التحكم، زر **"عرض النموذج الرسمي"** يفتح النموذج
معبَّأً بالبيانات بتخطيط SCI-M-02-F-01. اطبعه من المتصفح (Ctrl+P) واختر
"حفظ كـ PDF".

**اسم الموظف يظهر كـ "— محجوب حفاظاً على الخصوصية —"** في النسخة المُصدَرة،
بينما تبقى بقية البيانات (الرقم الوظيفي، الهاتف، البريد) ظاهرة.

## الإشعارات

جرس في أعلى الشاشة مع عدّاد يتحدّث كل 60 ثانية. تُنشأ الإشعارات تلقائياً عند:
تقديم مقترح · قرار فرز · إحالة للجنة · توقيع عضو · القرار التنفيذي ·
تعيين مسؤول تنفيذ · **تجاوز المهلة الزمنية**.

خدمة `SlaMonitorService` تفحص كل 15 دقيقة وتنبّه مديري النظام عن أي مقترح
تجاوز مهلة الفرز (دون تكرار التنبيه خلال 24 ساعة).

## الأمان — ما هو مطبَّق وما يحتاج عملاً قبل الإنتاج

**مطبَّق:**
- كلمات المرور مجزّأة بـ PBKDF2 (لا تُخزَّن صريحة أبداً).
- رموز جلسات عشوائية 48 بايت، صلاحية 12 ساعة.
- فلتر عام يرفض أي طلب غير موثَّق، ويمنع المستخدمين الموقوفين فوراً.
- تغيير كلمة المرور يبطل كل الجلسات الأخرى.
- قائمة بيضاء لامتدادات الملفات + حماية من Path Traversal.
- التحقق من الصلاحيات في الخادم (وليس الواجهة فقط).

**يحتاج عملاً قبل الإنتاج:**
- HTTPS إلزامي (حالياً HTTP للتطوير المحلي).
- ربط بـ Active Directory / SSO بدل الحسابات المحلية.
- فحص الملفات المرفوعة بمضاد فيروسات.
- تقييد CORS على نطاق الجمعية فقط.
- نقل تخزين المرفقات إلى تخزين مؤسسي عند التوسّع.
