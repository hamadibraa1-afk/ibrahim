# نظام الحضور الميداني — نسخة الاختبار الأولى

| المجلد | المحتوى |
| --- | --- |
| `src/FieldAttendance.Domain` | قواعد العمل والحسابات (بدون أي اعتماد خارجي) |
| `src/FieldAttendance.Api` | ASP.NET Core 8 Web API + EF Core + SQL Server |
| `web` | واجهة Angular 18 مبنية على Tailwind CSS (عربي/إنجليزي، وضع فاتح وداكن تلقائي) |

| `tests/FieldAttendance.Domain.Tests` | 180 اختبارًا لقواعد العمل |

النظام وحدتان: **الموظفون الإداريون** (الموارد البشرية) و**المحصّلون وفرق العمل الميداني**. من يملك صلاحية في الاثنتين تظهر له شاشة اختيار عند الدخول.

## المتطلبات

- .NET 8 SDK
- Node.js 20 أو 22
- SQL Server Express على `localhost\SQLEXPRESS` (نفس الإعداد السابق). لو اسم الـ instance مختلف، عدّل `ConnectionStrings:Default` في `src/FieldAttendance.Api/appsettings.json`.

## التشغيل — بالترتيب

نفّذ الخطوات بهذا التسلسل بالضبط. الخطوتان 1 و2 لمرة واحدة فقط.

### أول مرة بعد فك الضغط

**1. أنشئ هيكل قاعدة البيانات** (مرة واحدة):

```
scripts\db-new-migration.cmd Initial
```

إن كانت عندك قاعدة قديمة من نسخة سابقة، احذفها أولًا:

```
sqlcmd -S "localhost\SQLEXPRESS" -E -Q "IF DB_ID('FieldAttendance') IS NOT NULL BEGIN ALTER DATABASE FieldAttendance SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE FieldAttendance; END"
```

**2. ثبّت حزم الواجهة** (مرة واحدة):

```
cd web
npm install
```

**3. شغّل الخادم** — نافذة Terminal أولى تبقى مفتوحة:

```
cd src\FieldAttendance.Api
dotnet run -- --reset=true
```

أول تشغيل يبني قاعدة البيانات ويولّد البيانات التجريبية كاملة: المقرات والإدارات والموظفين، ونحو 2,680 بصمة حضور وانصراف على مدى ثمانين يومًا، مع الأذونات والإجازات والخصومات المرتبطة بها. **التوليد يستغرق من عشرين إلى أربعين ثانية** — انتظر حتى يظهر:

```
info: Now listening on: http://localhost:5000
```

Swagger على `http://localhost:5000/swagger`.

**4. شغّل الواجهة** — نافذة Terminal ثانية تبقى مفتوحة:

```
cd web
npm start
```

ثم افتح `http://localhost:4200` وادخل بـ **1005** وكلمة المرور `Test@1234` لتصل إلى وحدة الموارد البشرية والتقارير مباشرة.

### التشغيل اليومي بعد ذلك

```
cd src\FieldAttendance.Api
dotnet run
```

```
cd web
npm start
```

بدون `--reset=true` حتى لا تُمسح بياناتك، وبدون `npm install` إلا إذا تغيّرت الحزم.

### عند وصول نسخة جديدة مني

```
scripts\db-update.cmd
```

يطبّق ما تغيّر في الهيكل **بدون فقدان بيانات**. استخدم `--reset=true` فقط إذا أردت العودة للبيانات التجريبية من الصفر.

**الاختبارات:** `dotnet test` لقواعد العمل، و`npm run e2e:smoke` للواجهة بدون خادم، و`npm run e2e:full` للمسار الكامل. التفاصيل في `TESTING.md`.

| 1004 | جاسم مشرف المساجد | الميدان — مواقع المساجد الثلاثة فقط |

**البيانات التجريبية — الوحدة الإدارية:**

- **سبعة مقرات:** المقر الرئيسي، الذيد، المدام، البطايح، كلباء، خورفكان، دبا الحصن — بإحداثيات تقريبية لكل مدينة ونطاق تحقق.
- **ثماني إدارات:** تقنية المعلومات والتحول الذكي، المساعدات، المشاريع، الأيتام، العلاقات العامة والاتصال المؤسسي، الخدمات، التطوع، جمع التبرعات. لكل إدارة مدير، ولكل فرع مسؤول هو المدير المباشر لموظفيه.
- **45 موظفًا إداريًا** بأرقام 3001 إلى 3045، موزعين: 24 في المقر الرئيسي، والباقي على الفروع الستة (3 إلى 4 لكل فرع). لكل موظف راتب ومسمى ودرجة وجدول دوام ومدير مباشر. ويُضاف لهم حسابا الموارد البشرية (1005 و1006) بملفين كاملين.
- **جدولا دوام:** إداري 08:00–16:00 مع خميس أقصر حتى 14:00، وفروع 07:30–15:30.
- **سجل حضور لثمانين يومًا مضت** — نحو 2,680 بصمة دخول وخروج حقيقية:

  | الحالة | العدد التقريبي | أثرها |
  | --- | --- | --- |
  | حضور منضبط | 1,976 | — |
  | تأخير **بإذن معتمد** | 160 | يظهر في عمود "تأخير مبرر" ولا يُخصم منه شيء |
  | تأخير بلا إذن | 193 | يظهر "غير مبرر" ويولّد مقترح خصم |
  | انصراف مبكر **بإذن معتمد** | 59 | مبرر، بلا أثر مالي |
  | انصراف مبكر بلا إذن | 50 | غير مبرر ويولّد مقترح خصم |
  | إجازة معتمدة | 142 يومًا في 31 طلبًا | أيام إجازة في التقرير، وبعضها بدون راتب فيُخصم في الرواتب |
  | غياب بلا عذر | 99 | يولّد مقترح خصم يوم كامل |

- **219 إذنًا معتمدًا** (تأخير وانصراف مبكر) مربوطة ببصماتها: لكل إذن يوم فعلي وبصمة مطابقة وسبب مكتوب، واعتمدها مدير الموارد البشرية.
- **الفرق الذي يثبت صحة المنطق:** 462 يومًا تبدو في سجل البصمات تأخيرًا أو انصرافًا مبكرًا، لكن 219 منها مبررة بإذن معتمد فلا تدخل الخصومات ولا تؤثر في الراتب، و243 فقط هي القابلة للخصم. قارن عمودَي "مبرر" و"غير مبرر" في سجل الحضور لترى ذلك مباشرة.
- كل التأخيرات المولّدة تتجاوز فترة السماح، فالتمييز بين المبرر وغير المبرر ظاهر دائمًا ولا يختفي داخل السماح.
- الأرقام مولّدة ببذرة ثابتة، فالتصفير يعيد نفس التاريخ في كل مرة ويبقى أي رقم راجعته اليوم موجودًا غدًا.
- **خصومات وإنذارات مبنية على ذلك السجل:** نحو ستين مقترحًا **من الأيام غير المبررة وحدها** — ثلثها بانتظار القرار، وثلث معتمد بقيمة محسوبة من راتب صاحبه، وثلث محوّل إلى إنذار بدرجات متدرّجة، وبعضها عليه اعتراض من الموظف. الأيام التي عليها إذن معتمد لا يظهر لها مقترح إطلاقًا.
- **مستندات تقترب من الانتهاء** لموظفَين، لتظهر في تنبيهات الموارد البشرية.

**البيانات التجريبية — الوحدة الميدانية:**

- **20 محصّلًا** بالأرقام من 2001 إلى 2020.
- **10 مواقع في الشارقة:** سيتي سنتر، ميجا مول، ساحة الصحراء، أنصار مول، سفير مول، زيرو 6، متاجر الجرينة، مسجد الملك فيصل، مسجد النور، جامع الشارقة.
- **ثلاث مناوبات:** صباحية 08:00–16:00، مسائية 16:00–23:00، جزئية 09:00–13:00.
- **فجوات مقصودة:** ثلاثة مواقع بلا تخصيص (متاجر الجرينة، مسجد النور، جامع الشارقة)، وستة محصّلين بلا جدولة (2015–2020).
- **طلبات جاهزة:** إذن تأخير، إذن انصراف مبكر، إذن خروج مؤقت **معتمد** (يظهر زر "خروج بإذن" مباشرة للموظف 2002)، وطلب إجازة بانتظار القرار، وإجازة معتمدة للموظف 2007 اليوم والغد.
- **شكوى واقتراح** بانتظار المشرف.

الإحداثيات تقريبية لمواقع معروفة، فاضبط الموقع الذي ستجرّب منه بخيار "تحديد موقعي الحالي" أو بالضغط على الخريطة.

## تجربة التقارير

البيانات التجريبية مبنية خصيصًا لهذا الغرض. ادخل بـ **1005** (مدير الموارد البشرية) ← الموظفون الإداريون:

| ما تريد التحقق منه | الطريق |
| --- | --- |
| تقرير الحضور | التقارير ← تقرير الحضور ← من قبل 60 يومًا إلى اليوم ← "عرض وطباعة" أو "تحميل Word". جرّب تصفيته بإدارة واحدة. |
| بصمات الدخول والخروج | الحضور والانصراف ← اختر الفترة ← كل صف فيه وقت الدخول والخروج والتأخير وصافي العمل. |
| الخصومات والإنذارات | الخصومات والإنذارات ← تبويب المقترحات (بانتظار قرارك)، ثم تبويب الإنذارات لترى المُصدرة والمعترَض عليها. |
| الحساب النسبي للخصم | افتح مقترحين لموظفين برواتب مختلفة ولاحظ اختلاف القيمة عن اليوم نفسه. |
| **أثر الأذونات المعتمدة** | الحضور والانصراف ← صفِّ على "المتأخرون": سترى أيامًا بتأخير مبرر وأخرى غير مبرر. افتح الخصومات ولاحظ أن المبررة ليس لها مقترح. |
| الإجازات | الطلبات ← تبويب الإجازات ← الحالة "معتمدة": 31 طلبًا بتواريخ حقيقية، وأيامها تظهر "إجازة" في سجل الحضور. |
| دورة الرواتب | الرواتب ← فتح دورة لشهر مضى ← احتساب ← راجع الكشوف ← صدّر تقرير المالية. |
| سجل موظف واحد | ملفات الموظفين ← افتح أي ملف ← تبويب الدوام والراتب. |
| بوابة الموظف | اخرج وادخل بـ **3009** مثلًا ← حضوري ← اختر شهرًا سابقًا. |

## سيناريوهات الاختبار المقترحة

1. **اضبط الموقع على مكانك:** كمشرف ← المواقع ← تعديل "الفرع الرئيسي" ← "استخدم موقعي الحالي". بدون هذا، تسجيل الحضور راح يُرفض لأنك بعيد عن الإحداثيات التجريبية.
2. **الحضور:** افتح نافذة خاصة (Incognito) وادخل بـ ali ← اليوم ← تسجيل حضور. ارجع للمشرف وشوف الداشبورد.
3. **خارج النطاق:** في Chrome: F12 ← القائمة ⋮ ← More tools ← Sensors ← Location، اختر مدينة بعيدة ← سجّل حضور ← يظهر "طلب حضور استثنائي" ← اعتمده من صفحة الطلبات.
4. **الأذونات:** ali يطلب إذن انصراف مبكر ← المشرف يعتمد ← ali يسجّل انصراف ← صفحة الحضور تعرضه "مبرر".
5. **الخروج المؤقت:** إذن خروج مؤقت يغطي الوقت الحالي ← يظهر زر "خروج بإذن" ← "تسجيل عودة".
6. **الجدولة:** اضغط أي خانة في الجدول: تخصيص، تمديد، نقل مؤقت/دائم، استبدال، تغطية، إلغاء.
7. **التقييم:** المواقع ← رمز QR ← افتح الرابط في تبويب جديد وقيّم. جرّب وموظف حاضر، ووموظفان حاضران (يظهر اختيار الموظف).
8. **الإجازات:** ادخل بـ 2004 ← طلباتي ← نوع "طلب إجازة"، أو اعتمد الطلب الجاهز من حساب المشرف ولاحظ تحوّل أيام الموظف إلى "إجازة" وظهور الموقع "بلا تغطية".
9. **نطاق المشرف:** ادخل بـ 1002 ولاحظ أنه يرى موظفي المولات فقط، ثم بـ 1004 ليرى المساجد فقط. تُدار الإسنادات من صفحة المستخدمين ← زر "المواقع المسؤول عنها".
10. **البدلات:** صفحة البدلات ← نوع بدل جديد، ثم "منح بدل" لعدة موظفين بفترة بالأيام أو الأسابيع، ثم افتح سجل الحضور لترى عمود البدلات وتصديره لملف إكسل.
11. **الخريطة التفاعلية:** في **لوحة معلومات الوحدة الميدانية** (`/admin`) أسفل البطاقات مباشرة: كل موقع دائرة بلون حالته ونطاقه الجغرافي، والضغط عليه يبرز بطاقته. ادخل بـ 1002 أو 1001 ← المحصّلون وفرق العمل الميداني.
12. **التسجيل المبكر:** المناوبات فيها "السماح بالتسجيل المبكر" (45 دقيقة في البيانات التجريبية). سجّل حضورًا قبل الموعد ولاحظ أن ساعات العمل تُحتسب من بداية المناوبة بلا عمل إضافي.
13. **الصلاحيات:** ادخل بـ 1003 (مدير الإدارة) وتأكد أن أزرار التعديل والاعتماد مخفية وأن الخادم يرفض أي محاولة تعديل.
14. **الخريطة:** عند إضافة موقع، اضغط على الخريطة لتحديد النقطة، ثم احفظ.
15. **تعيين موظفين على موقع:** من صفحة المواقع ← "تعيين موظفين على الموقع" ← حدد الفترة وأيام العمل، وأضف صفًا لكل موظف بوقت دوامه. جرّب تعيين موظفين بأوقات مختلفة على نفس الموقع، وجرّب تعارضًا مقصودًا مع دوام موظف في موقع آخر لترى الرفض.
16. **الشكاوى:** من رابط التقييم ← "تسجيل شكوى" ← أكمل البيانات ← احتفظ بالرقم المرجعي، ثم افتحها من حساب المشرف وأغلقها بملاحظة.
17. **عدّاد الطلبات:** لاحظ أن الرقم بجانب "الطلبات والأذونات" ينقص فور اعتماد أي طلب بدون انتظار.

## الاختبار من الجوال

الجوال يحتاج HTTPS لتحديد الموقع:

```
cd web
npm run start:phone
```

افتح `https://<IP جهازك>:4200` من جوال على نفس الشبكة، واقبل تحذير الشهادة. قد تحتاج السماح للمنفذ 4200 في جدار حماية Windows.

## وحدة الموظفين الإداريين

- **ملفات الموظفين:** بيانات شخصية ووظيفية ومستندات ورواتب، مع سجل كامل لتغييرات الراتب.
- **الهيكل التنظيمي:** المقرات والفروع (تُضاف من صفحة الهيكل التنظيمي بخريطة ونطاق تحقق)، ثم الإدارات والأقسام، ولكل موظف مدير مباشر.
- **جداول الدوام:** دوام أسبوعي ثابت يختلف بين الأيام (خميس أقصر مثلًا).
- **الحضور:** يمر بنفس محرك حساب الوحدة الميدانية، فالأرقام لا تختلف بين الوحدتين. الجدول الأسبوعي يتحول تلقائيًا إلى تخصيصات يفهمها المحرك.
- **الإعدادات:** المسميات الوظيفية والدرجات وأنواع التعاقد والعطل الرسمية، كلها إضافة وتعديل وحذف بلا برمجة.
- **فصل المواقع:** صفحة "مواقع العمل" في الوحدة الميدانية تعرض مواقع الميدان فقط، والمقرات الإدارية تُدار من الهيكل التنظيمي في وحدة الموارد البشرية. النوعان لا يختلطان في أي قائمة.
- **لا تقييم ولا خريطة حيّة في الوحدة الإدارية:** رمز التقييم والشكاوى خاص بمواقع الميدان، والمقرات الإدارية بلا رمز. والخريطة التفاعلية تخص لوحة الميدان وحدها.
- **الصلاحيات:** مدير الموارد البشرية يعدّل، وأخصائي الموارد ومدير الإدارة يستعرضان، والرواتب لا يراها إلا مدير الموارد البشرية ومدير النظام.

- **الخصومات والإنذارات:** النظام يرصد المخالفات من الحضور ويقترح الخصم، ولا يُخصم شيء إلا بقرار. لكل مقترح أربعة خيارات: اعتماد، تخفيض المقدار، تحويله إلى إنذار، أو إلغاؤه بسبب. والقيمة تُحسب نسبة من راتب الموظف نفسه: يوم من راتب 5,000 يساوي 166.67، ويوم من راتب 2,000 يساوي 66.67.
- **الرواتب:** دورة شهرية تُفتح وتُحسب من الحضور والقرارات المعتمدة والبدلات، ثم تُعتمد وتُقفل. لا تُعتمد وفيها مقترح خصم أو طلب إجازة معلّق. كشف راتب لكل موظف، وتصدير تقرير الرواتب للمالية بملف إكسل.
- **بوابة الموظف:** الموظف الإداري يدخل بحسابه فيجد نظرة عامة على شهره، وسجل حضوره يومًا بيوم، وطلباته، وكشوف رواتبه المعتمدة، وملفه ودوامه ومستنداته، وإنذاراته مع حق الاعتراض.

- **مسار الموافقات:** لكل نوع طلب سلسلة اعتماد تُضبط من الإعدادات (افتراضيًا: رئيس القسم ← مدير الإدارة ← الموارد البشرية للإجازات، والمدير المباشر للأذونات). الطلب يظهر فقط لمن هو لديه الآن، والمستوى الذي لا شاغل له يُتخطّى بدل أن يُعطّل الطلب، ولا أحد يعتمد طلب نفسه. والموظف يتابع مسار طلبه خطوة بخطوة.
- **مباشرة العمل:** كل إجازة معتمدة تُنشئ سجل مباشرة تلقائيًا. الموظف يسجّل مباشرته من بوابته، والمدير يؤكدها، والتأخر عن المباشرة يظهر بعدد أيامه بدل أن يتحول غيابًا مجهول السبب.
- **التقارير:** ثلاثة تقارير (الحضور، الخصومات، مسيّر الرواتب) بصفحة عربية جاهزة للطباعة أو الحفظ PDF من المتصفح، أو تحميلها ملف Word.

**ملاحظة على التقارير:** اخترت توليد صفحة عربية بدل مكتبة PDF لأن معظم مكتبات PDF تكسر تشكيل الحروف العربية واتجاهها. المتصفح يطبع العربية بشكل صحيح، وملف Word يفتح مباشرة للتعديل.

## الشكاوى والاقتراحات

المتعامل يمسح رمز الموقع ← يقيّم الخدمة ← ويجد أسفل الصفحة زرَّي "تسجيل شكوى" و"تقديم اقتراح". يفتح له نموذجًا يطلب الاسم ورقم الهاتف والبريد (اختياري) والتفاصيل، ثم يمنحه **رقمًا مرجعيًا** بصيغة `SCI-2026-00001` للمتابعة.

المشرف يتابعها من صفحة "الشكاوى والاقتراحات" بتبويبين، مع استلام المتابعة والتصعيد والإغلاق بملاحظة إجراء، وحساب مدة المعالجة. الشكوى تُربط تلقائيًا بالموظف المناوب إن كان واحدًا فقط وقت التسجيل.

## الشعار والهوية

الشعار الرسمي للجمعية مركّب في `web/public/logo.png`، ويظهر في شاشة الدخول والقائمة الجانبية وتطبيق الموظف وصفحتي التقييم والشكاوى وبطاقة رمز الاستجابة السريعة المطبوعة. لتحديثه لاحقًا، استبدل الملف بنفس الاسم فقط.

ألوان الواجهة مأخوذة من الشعار نفسه: الأخضر `#008540` والبرتقالي `#e07f2e`، ومعرّفة في `src/styles.css` ضمن `--c-brand` و`--c-accent`، فأي تعديل للهوية يتم من مكان واحد.

## التنبيهات

جرس في أعلى كل واجهة يعرض ما ينتظر صاحبه. مصدران:

- **فوري:** طلب وصل لمرحلتك في مسار الاعتماد، أو صدر قرار على طلبك.
- **دوري كل نصف ساعة:** من تأخر عن مباشرة العمل (للمدير المباشر والموارد البشرية)، مستند يقترب من الانتهاء خلال 45 يومًا، ومقترحات خصم لم يُبتّ فيها.

**نص التنبيه لا يُخزَّن**، بل يُخزَّن نوعه وقيمه، ويُعرض بلغة القارئ. ولكل تنبيه مفتاح ثابت يمنع تكراره مهما تكرر الفحص.

**البريد والرسائل النصية:** البنية جاهزة بواجهة قنوات، والقناتان الحاليتان تسجّلان ما كان سيُرسل في سجل الخادم. ربط مزوّد فعلي يحتاج إضافة محوّل واحد وإعداداته، دون لمس أي كود آخر. لم أربط مزوّدًا لأن ذلك يحتاج حسابكم وتجربة حقيقية لا أستطيعها في بيئتي.

## ضوابط السلامة المالية والزمنية

- **البيانات القديمة لا تحتاج تحويلًا:** عمود `datetimeoffset` يحفظ اللحظة مع إزاحتها، فالقيمة المخزّنة بـ +04:00 هي نفس اللحظة المخزّنة بـ +00:00. سكربت `scripts\db-check-times.sql` يتحقق من ذلك ويعرض توزيع الإزاحات.
- **التوقيت:** كل لحظة تُخزَّن بـ UTC، والوقت المحلي للعمل يأتي من إعداد `Attendance:TimeZone` (افتراضيًا `Asia/Dubai`). تغيير المنطقة أو إضافة فرع في بلد آخر لا يحتاج تعديل كود، وخادم بمنطقة مختلفة لا يزيح أي تسجيل.
- **قفل فترة الرواتب:** الشهر الذي اعتُمدت أو أُقفلت رواتبه يصبح مغلقًا: لا اعتماد إذن، ولا قرار خصم، ولا اعتماد أو إلغاء إجازة تخصه. التصحيح يتم في دورة لاحقة بقيد صريح.
- **منع التعارض مع الإجازات:** لا يُقبل تسجيل حضور في يوم إجازة معتمدة، ولا تُعتمد إجازة على أيام سُجّل فيها حضور فعلي.
- **الصلاحيات ضد الوصول غير المصرّح (IDOR):** أي طلب يحمل معرّف موظف في الرابط يمر بتحقق: مدير النظام والموارد البشرية يرون الجميع، ومدير الإدارة موظفي إدارته، والموظف نفسه فقط سجله. الرفض من الخادم لا من إخفاء الأزرار.
- **الورديات الليلية:** الوردية التي تتخطى منتصف الليل تُحسب كاملة — التأخير وفترة السماح والانصراف المبكر والعمل الإضافي — ومثبّتة بعشرة اختبارات مستقلة.

## نظام التصميم

- Tailwind CSS مع طبقة مكوّنات في `src/styles.css` (الأزرار، البطاقات، الحقول، الجداول، النوافذ) حتى تبقى الشاشات متناسقة.
- الألوان معرّفة كمتغيّرات CSS، فالوضع الداكن يتبع إعداد الجهاز تلقائيًا بدون كود إضافي.
- كل الأدوات الاتجاهية منطقية (`ms-`, `pe-`, `border-s`) لتعمل بالعربية والإنجليزية من نفس الكود.

## ملاحظات مهمة لهذه النسخة

- **دقة GPS في وضع التطوير 2000 متر** لأن أجهزة الكمبيوتر تحدد الموقع عبر الواي فاي بدقة ضعيفة. في الإنتاج 100 متر (`appsettings.json`).
- **قاعدة البيانات تعمل بـ EF Migrations.** نفّذ `scripts\db-new-migration.cmd Initial` مرة واحدة، وبعدها كل نسخة جديدة تحتاج `scripts\db-update.cmd` فقط **بدون فقدان بيانات**. التفاصيل في `MIGRATIONS.md`. الإنتاج يرفض العمل بلا Migrations، و`--reset` يعمل في التطوير فقط.
- **مفتاح التوقيع في `appsettings.Development.json` للتطوير فقط.**
- **الصلاحيات مطبّقة في الخادم** وليست إخفاء أزرار فقط: مدير الإدارة يستعرض ولا يعدّل، وإدارة الحسابات لمدير النظام وحده.
- **المهام الزمنية** (الانصراف التلقائي، تسجيل الغياب، إنشاء سجلات اليوم) تعمل داخل الـ API كل دقيقة.
